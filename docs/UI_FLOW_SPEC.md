# 页面流程、交互规格、边界条件

## 1. 页面流程

### 1.1 应用启动流程

```
用户访问应用
    ↓
index.html 加载
    ↓
HashRouter 初始化
    ↓
默认路由 "/" 重定向到 "/home"
    ↓
显示 Home 页面
```

### 1.2 主要页面流程

#### Home 页面流程
```
进入 /home
    ↓
显示 Header（用户信息 + 通知）
    ↓
显示 "Enterprise Tools" 标题
    ↓
渲染工具卡片网格（2列布局，10个工具）
    ↓
用户点击工具卡片
    ↓
[当前：无后续操作]
[预期：导航到对应工具页面或打开工具功能]
```

#### AspireAI 页面流程
```
进入 /aspireAI
    ↓
显示 Header（用户信息 + 通知）
    ↓
检查是否有历史消息
    ↓
无消息：显示常见问题按钮
有消息：显示对话历史
    ↓
用户输入问题或点击常见问题
    ↓
发送消息到 Gemini API
    ↓
显示加载状态（三个跳动的点）
    ↓
接收 AI 响应
    ↓
显示响应消息
    ↓
自动滚动到底部
```

#### Settings 页面流程
```
进入 /settings
    ↓
显示 "Settings" 标题
    ↓
显示设置选项列表（5个选项）
    ↓
用户点击设置选项
    ↓
[当前：无后续操作]
[预期：导航到对应设置子页面或打开设置对话框]
    ↓
用户点击 "Log Out"
    ↓
[当前：无后续操作]
[预期：执行登出逻辑，清除会话，跳转到登录页]
```

### 1.3 导航流程

```
用户在任何页面
    ↓
点击底部导航栏
    ↓
底部导航栏按钮（Home / aspireAI / Settings）
    ↓
路由切换
    ↓
对应页面加载
    ↓
底部导航栏高亮当前页面
```

## 2. 交互规格

### 2.1 Home 页面交互

#### Header 区域
- **用户头像**：
  - 位置：左上角
  - 尺寸：48px × 48px（`size-12`）
  - 样式：圆形，带边框 `border-2 border-[#3b4754]`
  - 图片来源：`https://picsum.photos/seed/alex/100/100`（占位图）
  - 交互：当前无点击行为

- **用户信息**：
  - 问候语：`Good morning, Liz`（硬编码）
  - 角色标签：`Newbie Agent`（硬编码）
  - 样式：白色文字，字体大小 `text-lg`（问候语），`text-sm`（角色）

- **通知按钮**：
  - 位置：右上角
  - 样式：圆形按钮，40px × 40px
  - 状态指示：红色圆点提示（`bg-red-500`）
  - Hover 效果：背景色变为 `hover:bg-[#283039]`
  - 交互：当前无点击行为

#### 工具卡片网格
- **布局**：2列网格（`grid-cols-2`）
- **间距**：卡片间距 `gap-3`，底部外边距 `mb-6`
- **卡片样式**：
  - 背景：`bg-[#1c2127]`
  - 边框：`border border-[#3b4754]`
  - 圆角：`rounded-xl`
  - 内边距：`p-4`
  - 阴影：`shadow-sm`

- **卡片交互**：
  - Hover：边框颜色变为 `border-primary`，标题颜色变为 `text-primary`
  - Active：轻微缩放 `active:scale-95`
  - 过渡：`transition-all duration-200`
  - 光标：`cursor-pointer`
  - **当前状态**：点击无后续操作

#### 工具卡片内容
每个卡片包含：
1. **图标区域**：
   - 尺寸：40px × 40px（`w-10 h-10`）
   - 背景：根据工具类型有不同颜色（`bg-{color}-500/10`）
   - 图标：Material Symbols，颜色对应工具主题色

2. **文本区域**：
   - 标题：`text-white text-base font-bold`
   - 副标题：`text-[#9dabb9] text-xs`

### 2.2 AspireAI 页面交互

#### Header 区域
- 与 Home 页面相同的 Header 设计

#### 聊天区域
- **初始状态**（无消息时）：
  - 显示提示文本："Get started with these common questions:"
  - 显示 4 个常见问题按钮：
    1. "How is the brokerage structured?"
    2. "Can you walk me through the full transaction process from first contact to closing?"
    3. "What does the onboarding and training timeline look like?"
    4. "Which CRM systems are mandatory?"
  - 按钮样式：
    - 背景：`bg-[#1c2127]`
    - 边框：`border border-[#3b4754]`
    - Hover：`hover:bg-[#283039] hover:border-primary/50`
    - 禁用状态：`disabled:opacity-50 disabled:cursor-not-allowed`

#### 消息显示
- **用户消息**：
  - 对齐：右对齐（`justify-end`）
  - 最大宽度：85%（`max-w-[85%]`）
  - 样式：`bg-primary text-white`
  - 圆角：`rounded-2xl rounded-tr-none`（右上角不圆角）
  - 内边距：`px-4 py-2`

- **AI 消息**：
  - 对齐：左对齐（`justify-start`）
  - 最大宽度：85%（`max-w-[85%]`）
  - 样式：`bg-[#283039] text-white`
  - 圆角：`rounded-2xl rounded-tl-none`（左上角不圆角）
  - 内边距：`px-4 py-2`

#### 加载状态
- **加载指示器**：
  - 位置：左侧（AI 消息位置）
  - 样式：三个跳动的圆点
  - 动画：`animate-bounce`，延迟分别为 0s、0.2s、0.4s
  - 颜色：`bg-primary`

#### 输入区域
- **位置**：固定在底部（`fixed bottom-16`）
- **容器样式**：
  - 背景：`bg-background-dark/80 backdrop-blur-md`
  - 内边距：`px-4 pb-2`
  - Z-index：`z-40`

- **输入框容器**：
  - 背景：`bg-[#1c2127]`
  - 边框：`border border-[#3b4754]`
  - 圆角：`rounded-xl`
  - 阴影：`shadow-lg`
  - 内边距：`p-2`

- **AI 图标**：
  - 位置：输入框左侧
  - 尺寸：32px × 32px
  - 背景：`bg-primary/10`
  - 图标：`auto_awesome`

- **输入框**：
  - 样式：透明背景，白色文字
  - 占位符：`Welcome! How can I help you today?`
  - 占位符颜色：`placeholder-[#9dabb9]`
  - 回车键：触发发送（`onKeyDown` 监听 Enter）

- **麦克风按钮**：
  - 图标：`mic`
  - Hover：`hover:bg-[#283039]`
  - **当前状态**：UI 已存在，功能未实现

- **发送按钮**：
  - 文本：`Send`（未处理时）/ `...`（处理中）
  - 样式：
    - 正常：`bg-primary hover:bg-blue-600`
    - 禁用：`bg-gray-600 cursor-not-allowed`
  - 禁用条件：`isProcessing || !input.trim()`

#### 自动滚动
- **触发时机**：消息列表更新时（`useEffect` 监听 `messages`）
- **行为**：平滑滚动到底部（`scrollIntoView({ behavior: "smooth" })`）

### 2.4 底部导航栏交互

#### 导航栏样式
- **位置**：固定在底部（`fixed bottom-0`）
- **背景**：`bg-[#1c2127]`
- **边框**：顶部边框 `border-t border-[#283039]`

- **Z-index**：`z-50`

- **间距**：项目间 `gap-1`

#### 导航项状态

  - 图标颜色：`text-[#9dabb9]`

### 2.5 通用交互模式

#### 页面切换动画
- **当前**：无页面切换动画（直接切换）
- **路由**：使用 HashRouter，URL 变化为 `#/home`, `#/aspireAI`, `#/settings`

#### 滚动行为
- **主内容区域**：`overflow-y-auto`，可垂直滚动
- **滚动条样式**：自定义样式（宽度 4px，颜色 `#3b4754`）

#### 响应式断点
- **容器最大宽度**：`max-w-md`（约 448px）
- **居中方式**：`mx-auto`
- **适用设备**：移动端和小屏幕设备

## 3. 边界条件

### 3.1 网络边界条件

#### API 调用失败
- **场景**：Gemini API 调用失败（网络错误、API Key 无效等）
- **处理**：
  - 捕获错误并记录到控制台（`console.error`）
  - 显示友好错误消息："Error: Unable to connect to the intelligence service. Please try again later."
  - UI 状态：移除加载状态，允许用户重试

#### API Key 未配置
- **场景**：`GEMINI_API_KEY` 环境变量未设置
- **处理**：
  - 返回消息："API Key is not configured. Please check your environment."
  - 不会抛出异常，用户体验可接受

#### 网络超时
- **场景**：API 响应超时
- **当前处理**：依赖浏览器默认超时行为
- **建议改进**：添加超时处理和重试机制

### 3.2 输入边界条件

#### 空输入
- **场景**：用户尝试发送空消息
- **处理**：发送按钮禁用（`disabled={!input.trim()}`）
- **用户体验**：按钮显示为禁用状态，无法点击

#### 超长输入
- **场景**：用户输入超长文本
- **当前处理**：无长度限制
- **潜在问题**：可能影响 API 调用成本和响应时间
- **建议改进**：添加最大长度限制（如 1000 字符）

#### 特殊字符和换行
- **场景**：输入包含特殊字符、换行符等
- **当前处理**：作为普通文本处理
- **注意**：换行符在输入框中不会显示，但会包含在发送的消息中

### 3.3 UI 边界条件

#### 消息数量过多
- **场景**：对话历史很长，消息列表很长
- **当前处理**：
  - 消息列表可滚动（`overflow-y-auto`）
  - 自动滚动到底部
- **潜在问题**：性能可能下降，内存占用增加
- **建议改进**：实现虚拟滚动或消息分页

#### 屏幕尺寸极端情况
- **超大屏幕**：
  - 当前：容器限制为 `max-w-md`，居中显示
  - 体验：左右留白，不影响功能

- **极小屏幕**：
  - 当前：使用响应式布局，但未定义最小宽度
  - 潜在问题：极端小屏幕可能布局混乱

#### 文本溢出
- **场景**：AI 响应或用户输入文本过长
- **当前处理**：消息框限制最大宽度 85%，文本自动换行
- **潜在问题**：超长单词可能溢出

### 3.4 状态边界条件

#### 并发请求
- **场景**：用户在 AI 处理中时再次点击发送
- **处理**：发送按钮和输入处理都有 `isProcessing` 检查
- **行为**：新的请求被阻止，直到当前请求完成

#### 页面切换时的异步操作
- **场景**：用户在 AI 响应返回前切换页面
- **当前处理**：React 组件卸载时，setState 调用会被忽略（React 18+）
- **潜在问题**：可能出现内存泄漏警告（如果使用了过时的模式）
- **当前代码**：使用了函数式组件和 Hooks，通常不会有此问题

#### 快速连续点击
- **场景**：用户快速连续点击导航按钮或工具卡片
- **处理**：React Router 和按钮状态管理会处理重复点击
- **体验**：可能看到短暂的加载状态或闪烁

### 3.5 数据边界条件

#### 用户信息硬编码
- **场景**：用户信息（姓名、角色、头像）为硬编码
- **当前状态**：所有用户看到相同信息
- **影响**：不影响核心功能，但缺乏个性化

#### 工具列表静态数据
- **场景**：工具列表来自 `constants.tsx`，为静态数据
- **影响**：无法动态配置，修改需要重新构建

#### 对话历史未持久化
- **场景**：刷新页面后对话历史丢失
- **影响**：用户体验不便，无法查看历史对话

### 3.6 浏览器兼容性边界条件

#### 不支持 ES6+ 的浏览器
- **场景**：用户使用旧版浏览器
- **当前状态**：应用使用现代 JavaScript 特性
- **影响**：旧版浏览器可能无法运行

#### 禁用 JavaScript
- **场景**：用户浏览器禁用 JavaScript
- **影响**：应用无法运行（React 应用需要 JavaScript）

#### 网络连接不稳定
- **场景**：网络连接时断时续
- **当前处理**：错误消息提示，用户可重试
- **建议改进**：添加离线检测和离线提示

### 3.7 性能边界条件

#### 初始加载时间
- **场景**：首次访问需要加载 CDN 资源（Tailwind CSS、Material Symbols、React 等）
- **影响**：依赖网络速度，可能加载较慢

#### 大量重渲染
- **场景**：消息列表很长时频繁更新
- **当前处理**：使用 React Hooks，依赖优化
- **潜在问题**：极端情况下可能性能下降

#### 内存泄漏风险
- **场景**：长时间使用，消息列表不断增长
- **当前处理**：组件卸载时自动清理
- **建议改进**：限制消息历史数量或实现清理机制

## 4. 错误处理规范

### 4.1 用户可见错误
- **API 错误**：显示友好提示，不暴露技术细节
- **网络错误**：提示重试
- **配置错误**：提示检查环境变量

### 4.2 开发者可见错误
- **控制台日志**：API 错误记录到 `console.error`
- **错误消息**：包含足够上下文便于调试

### 4.3 错误恢复
- **自动恢复**：移除错误状态，允许用户继续操作
- **手动恢复**：用户可重试失败的操作

## 5. 可访问性考虑

### 5.1 当前状态
- **键盘导航**：部分支持（输入框、按钮可聚焦）
- **屏幕阅读器**：未添加 aria 标签
- **颜色对比度**：基本满足，但未专门测试
- **焦点指示**：依赖浏览器默认，可能需要改进

### 5.2 改进建议
- 添加 aria-label 到图标按钮
- 改善焦点可见性
- 确保所有交互元素可通过键盘访问
- 添加跳过导航链接
